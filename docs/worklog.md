**Files touched**

The `<button>` only renders when `eligible`, but the `role="alert"` message renders whenever `message` is set, regardless of eligibility — so the mutation/hook instance and its message now survive the eligibility flip driven by the post-error refetch.
- `src/__tests__/t2/dashboard.test.jsx` — added regression test `T-2 TransactionTable row retry (FR-7 row case, review fix)`: clicks Retry on `txn_6` (FAILED, retry_eligible), MSW returns 409 NOT_RETRYABLE and flips the store's `retry_eligible` to `false` for that row; asserts the row's Retry `<button>` disappears once the refetch reflects `retry_eligible: false` while the `role="alert"` "This transaction's status changed" message remains visible in that same row.
